# 前端开发计划书

## 1. 项目背景

当前项目原本是武器知识图谱方向，现阶段需要改造为医药方向。后端已经提供了医药相关接口雏形，包括药材、分类、产地、来源、方剂、知识图谱、AI 问答和 mock 数据接口。前端可以不等待后端全部完成，先基于现有接口和 mock 数据进行页面开发与交互改造。

前端开发主要目标是将旧项目中的武器领域页面、字段、文案和交互替换为医药领域内容，并逐步对接后端医药 API。

## 2. 前端开发目标

1. 完成旧武器方向页面向医药方向的改造。
2. 完成药材搜索、筛选、列表展示和详情展示。
3. 完成知识图谱可视化页面的医药节点类型替换和交互改造。
4. 完成 AI 问答页面或推荐结果页面的基础交互。
5. 完成登录、注册和用户信息展示相关前端流程。
6. 如项目需要，完成管理后台或数据上传页面的基础功能。
7. 后端真实接口未稳定前，使用 mock 数据保证前端页面可独立开发和演示。

## 3. 开发范围

### 3.1 页面开发范围

| 页面 | 开发内容 |
|---|---|
| 首页 | 项目入口、药材统计、热门药材、分类入口、搜索入口 |
| 登录页 | 用户登录表单、token 保存、登录状态判断 |
| 注册页 | 用户注册表单、注册后自动登录或跳转登录 |
| 药材搜索页 | 搜索框、搜索结果、分类筛选、产地筛选、分页 |
| 药材详情页 | 药材基础信息、分类、产地、来源、性味、归经、功效、用法用量、注意事项、图片 |
| 知识图谱页 | D3 图谱渲染、节点点击、拖拽、缩放、节点详情侧边栏 |
| 方剂页 | 方剂列表、方剂详情、组成药材展示 |
| AI 问答页 | 问题输入、回答展示、加载状态、离线回答提示 |
| 管理后台 | 药材新增、编辑、删除、图片上传、基础数据管理 |

### 3.2 字段替换范围

旧武器字段需要替换为医药字段：

| 旧字段 | 新字段 |
|---|---|
| 武器名称 | 药材名称 / 药品名称 |
| 武器类型 | 药材分类 / 药品类别 |
| 产地 / 制造国家 | 产地 / 道地产区 |
| 制造商 | 来源 / 基源 |
| 性能参数 | 性味、归经、功效、用法用量 |
| 武器描述 | 药材描述 / 功效主治 |
| 武器图片 | 药材图片 |

知识图谱节点类型替换：

| 旧节点 | 新节点 |
|---|---|
| Weapon | Herb |
| Type | Category |
| Country | Region |
| Manufacturer | Source |
| Model | Property / Meridian / Efficacy |

## 4. 接口对接计划

接口整理文档见：`frontend-api-guide.md`。

前端优先对接以下接口：

### 4.1 第一优先级接口

| 功能 | 接口 |
|---|---|
| 药材列表 | `GET /api/herbs?page=1&limit=20` |
| 药材搜索 | `GET /api/herbs/search?q=关键词` |
| 药材详情 | `GET /api/herbs/:id` |
| 药材分类 | `GET /api/herb-categories` |
| 产地筛选 | `GET /api/herb-regions` |
| 药材统计 | `GET /api/herbs/statistics` |

### 4.2 第二优先级接口

| 功能 | 接口 |
|---|---|
| 知识图谱 | `GET /api/knowledge/graph-data` |
| 图谱节点详情 | `GET /api/knowledge/herb-details/:herbName` |
| 地区分布 | `GET /api/knowledge/region-distribution` |
| 方剂列表 | `GET /api/formulas` |
| 方剂详情 | `GET /api/formulas/:id` |

### 4.3 第三优先级接口

| 功能 | 接口 |
|---|---|
| 登录 | `POST /api/auth/login` |
| 注册 | `POST /api/auth/register` |
| 用户资料 | `GET /api/auth/profile` |
| AI 问答 | `POST /api/ai-gateway/chat` |
| 药材分析 | `POST /api/ai-gateway/analyze-herb` |
| 配伍禁忌 | `POST /api/ai-gateway/check-compatibility` |
| 图片上传 | `POST /api/herb-images/:herbId` |

### 4.4 Mock 接口使用

后端接口未启动或数据不稳定时，先使用：

```text
GET /api/mock/herbs
GET /api/mock/herbs/:id
GET /api/mock/herb-categories
GET /api/mock/herb-regions
GET /api/mock/formulas
GET /api/mock/formulas/:id
GET /api/mock/knowledge-graph
POST /api/mock/chat
```

前端封装 API 时建议保留统一切换配置，例如：

```js
const USE_MOCK = false;
const API_BASE = 'http://localhost:3001/api';
```

## 5. 技术实现计划

### 5.1 请求封装

先统一封装请求方法，处理：

1. `baseURL` 配置。
2. `Authorization: Bearer <token>` 自动携带。
3. `success/message/data` 统一解析。
4. 请求失败、登录失效、空数据等状态处理。
5. mock 接口和真实接口切换。

建议新增或整理前端 API 模块：

```text
scripts/api.js
scripts/herb-api.js
scripts/auth-api.js
scripts/graph-api.js
scripts/ai-api.js
```

如果项目继续使用原生 HTML + JS，可以保持当前结构，不强行迁移框架。

### 5.2 页面状态设计

每个主要页面至少处理以下状态：

1. 初始加载状态。
2. 加载成功状态。
3. 空数据状态。
4. 请求失败状态。
5. 表单提交中状态。
6. 登录失效状态。

### 5.3 前端本地存储

建议使用 `localStorage` 保存：

| key | 内容 |
|---|---|
| `token` | 登录 token |
| `user` | 当前用户基本信息 |
| `lastSearchKeyword` | 最近搜索关键词，可选 |
| `theme` | 主题配置，可选 |

## 6. 开发阶段安排

### 第一阶段：准备与基础改造

时间建议：1-2 天。

任务：

1. 拉取并确认 `shx` 或当前目标分支代码。
2. 从目标分支新建自己的前端开发分支。
3. 阅读 `frontend-api-guide.md`。
4. 确认项目当前前端入口和脚本结构。
5. 全局替换明显的武器领域文案为医药领域文案。
6. 封装基础 API 请求方法。

交付物：

1. 前端分支创建完成。
2. 基础请求封装完成。
3. 页面主导航和基础文案完成医药化。

### 第二阶段：药材核心页面

时间建议：2-4 天。

任务：

1. 开发或改造药材搜索页。
2. 开发药材列表展示。
3. 接入分类和产地筛选。
4. 开发药材详情页。
5. 展示性味、归经、功效、用法用量、注意事项。
6. 接入药材图片展示。

交付物：

1. 药材搜索可用。
2. 药材列表可筛选。
3. 药材详情可查看。

### 第三阶段：知识图谱页面

时间建议：2-4 天。

任务：

1. 将旧武器图谱节点类型改为医药节点类型。
2. 接入 `/api/knowledge/graph-data` 或 mock 图谱数据。
3. 完成节点颜色、图例、标签显示。
4. 完成节点点击展示详情侧边栏。
5. 保留拖拽、缩放、搜索定位等交互。

交付物：

1. 医药知识图谱可正常渲染。
2. 节点点击后能展示药材详情。
3. 图谱交互无明显错误。

### 第四阶段：AI 问答与方剂页面

时间建议：2-3 天。

任务：

1. 改造 AI 问答页面。
2. 先接入 `/api/mock/chat`，再切换 `/api/ai-gateway/chat`。
3. 展示 AI 回答、加载状态和失败提示。
4. 开发方剂列表和详情页。
5. 展示方剂组成药材、剂量、角色和来源。

交付物：

1. AI 问答基础可用。
2. 方剂列表和详情可查看。

### 第五阶段：登录与管理功能

时间建议：2-4 天。

任务：

1. 完成登录、注册、退出登录。
2. 根据 `role === 'admin'` 控制管理入口显示。
3. 完成药材新增、编辑、删除表单。
4. 完成药材图片上传。
5. 完成基础数据管理入口，如分类、产地、来源。

交付物：

1. 用户登录态可用。
2. 管理员可进行基础数据维护。
3. 图片上传和展示可用。

### 第六阶段：联调与优化

时间建议：2-3 天。

任务：

1. 与后端确认接口字段是否稳定。
2. 将 mock 数据逐步替换为真实接口。
3. 修复接口字段不一致问题。
4. 检查所有页面的空状态、错误状态、加载状态。
5. 检查移动端和桌面端布局。
6. 整理前端开发说明。

交付物：

1. 前端主要流程可演示。
2. 页面无明显旧武器文案残留。
3. 可以提交合并请求。

## 7. Git 分支计划

建议流程：

```powershell
git switch shx
git pull origin shx
git switch -c feature/frontend-medical
```

日常开发：

```powershell
git status
git add .
git commit -m "完成药材搜索页改造"
```

推送自己的分支：

```powershell
git push origin feature/frontend-medical
```

后续如果 `shx` 更新：

```powershell
git switch shx
git pull origin shx
git switch feature/frontend-medical
git merge shx
```

解决冲突后：

```powershell
git add .
git commit
```

## 8. 风险与注意事项

1. 后端接口字段可能继续变化，前端请求封装要集中管理，避免每个页面散写 `fetch`。
2. 旧项目仍有大量 weapon 命名，改造时要区分显示文案和代码变量。变量可以逐步改，不建议一次性大规模重命名导致功能失效。
3. 知识图谱页面逻辑复杂，先保证数据能渲染，再优化样式和交互。
4. AI 接口需要登录，并且 Deepseek 或 Python 服务可能未配置，前端要支持 `offline: true` 的降级结果展示。
5. 图片上传需要 `multipart/form-data`，不要手动设置 JSON 类型。
6. 管理接口涉及权限，前端只负责控制入口，真正权限以后端返回为准。
7. 页面里不要继续使用旧的 `/api/weapons` 路径，应改为 `/api/herbs` 等新路径。

## 9. 验收标准

### 基础验收

1. 首页能展示医药方向内容。
2. 药材搜索可以输入关键词并展示结果。
3. 药材详情页字段完整，无旧武器字段残留。
4. 分类和产地筛选可用。
5. 知识图谱能展示医药节点和关系。
6. 节点点击后能展示详情。
7. 登录和注册页面可正常提交。
8. AI 问答页面能展示回答或离线降级回答。

### 代码验收

1. 请求接口统一封装。
2. 页面无明显重复请求逻辑。
3. 主要交互有加载和错误提示。
4. 不直接在多个页面硬编码后端地址。
5. Git 提交记录清晰。

## 10. 当前建议优先做的三件事

1. 从 `shx` 或目标分支新建自己的前端分支。
2. 先完成 API 请求封装和 mock/真实接口切换。
3. 优先改药材搜索页、药材列表页、药材详情页。
