# 三路混合检索 + RRF 融合 技术方案与可行性分析

> 目标：将当前「图检索为主 + 向量检索可选补充」升级为「BM25 + 向量 + 知识图谱」三路并行检索，并用 RRF 融合重排，提升检索准确率与召回率。

---

## 一、现状分析（当前检索实现）

### 当前检索链路（`ragServiceV2.js` 的 `ragViaManual`）

```
问题
 → 本地 n-gram 关键词提取
 → 图检索 searchNeo4j（CONTAINS 字面匹配）
     ├─ 第1轮：h.name CONTAINS term（精确名称）
     ├─ 第2轮：description/efficacy/pinyin CONTAINS term（扩展，<2 时触发）
     └─ 方剂：f.name/f.description CONTAINS term
 → 向量检索（可选，embeddingService.isReady() 才执行）
     └─ text-embedding-v3 余弦相似度，命中新药材补到前面
 → 1-2 跳图遍历 → LLM 知识增强 → DeepSeek 生成
```

### 当前三大痛点

1. **字面匹配粗糙**：`CONTAINS` 是子串匹配，没有词频/逆文档频率（TF-IDF）的权重，命中排序无科学依据。
2. **向量检索是"串行可选"**：在图检索之后补充，且依赖 `isReady()`，缺 key 就降级，不是同级并行。
3. **无融合机制**：图检索和向量检索结果是"拼接"，没有统一的排序打分。

---

## 二、目标架构（三路并行 + RRF 融合）

```
用户问题
   │
   ├── 路1：BM25 全文检索（Neo4j 全文索引 cjk）──┐
   ├── 路2：向量语义检索（text-embedding-v3）────┼─→ RRF 融合重排 → 统一结果 → LLM
   └── 路3：知识图谱检索（Cypher + 多跳）────────┘
```

- 三路用 `Promise.all` 并行执行，总延迟 ≈ 最慢一路
- 各路返回 `[{ name, score, source }]`，交给 RRF 融合

---

## 三、每一路的技术实现

### 路 1：BM25 全文检索（新增）

**建全文索引（cjk 分析器处理中文）**：

```cypher
CREATE FULLTEXT INDEX herb_fulltext IF NOT EXISTS
FOR (h:Herb) ON EACH [h.name, h.pinyin, h.description, h.efficacy]
OPTIONS { indexConfig: { `fulltext.analyzer`: 'cjk' } }
```

**BM25 查询**：

```cypher
CALL db.index.fulltext.queryNodes('herb_fulltext', $query)
YIELD node, score
RETURN node.name AS name, score
LIMIT 20
```

**JS 封装（新方法 `searchBM25`）**：

```js
async searchBM25(query) {
  const session = neo4jManager.getSession();
  const result = await session.run(
    "CALL db.index.fulltext.queryNodes('herb_fulltext', $query) " +
    "YIELD node, score RETURN node.name AS name, score LIMIT 20",
    { query }
  );
  return result.records.map(r => ({
    name: r.get('name'),
    score: r.get('score'),   // Lucene BM25 分数
    source: 'bm25'
  }));
}
```

### 路 2：向量语义检索（已有，升级并行）

复用现有 `embeddingService.search(query, k)`，返回 `[{ name, score }]`，只需补上 `source: 'vector'`。

```js
const vectorResults = await embeddingService.search(question, 20);
// → [{ name, score: 余弦相似度, source: 'vector' }]
```

### 路 3：知识图谱检索（已有，需补排名分）

复用 `searchNeo4j`，但需为结果补一个"图排名分"（当前无 score）。按匹配优先级给分：

| 匹配方式 | 图分（source='graph'） |
|---|---|
| name 精确匹配 | 3.0 |
| description/efficacy/pinyin 匹配 | 2.0 |
| 方剂匹配 | 1.0 |

## 四、RRF 融合算法（核心新增）

**RRF（Reciprocal Rank Fusion）**：各路结果按排名取倒数求和，总分重排，无需训练、无需调参。

```js
function rrfFusion(resultsList, k = 60) {
  // resultsList: [[{name, score, source}], ...] 三路各自已排序的结果
  const fused = new Map();
  for (const results of resultsList) {
    results.forEach((item, rank) => {
      if (!item || !item.name) return;
      const rrf = 1 / (k + rank + 1);   // 排名越靠前，rrf 分越高
      if (!fused.has(item.name)) {
        fused.set(item.name, { name: item.name, score: 0, sources: new Set() });
      }
      const entry = fused.get(item.name);
      entry.score += rrf;
      entry.sources.add(item.source);   // 记录命中了哪几路
    });
  }
  return Array.from(fused.values())
    .sort((a, b) => b.score - a.score)
    .map(e => ({ name: e.name, rrfScore: e.score, sources: [...e.sources] }));
}
```

**示例**：某药材在 BM25 排第 1、向量排第 3、图检索排第 5：
```
rrf = 1/(60+1) + 1/(60+3) + 1/(60+5) ≈ 0.0164 + 0.0159 + 0.0154 ≈ 0.0477
```

多路同时命中的药材会累积高分，排到最前。

## 五、融合后的完整链路

```
问题 → 三路并行检索（Promise.all）
   → RRF 融合重排 → 得到排序后的药材名列表
   → searchNeo4jByNames 批量取完整字段（复用现有）
   → 1-2 跳图遍历 → LLM 知识增强 → 生成答案
   → pipelineSteps 记录：各路命中数 + 各自排名 + RRF 融合分
```

## 六、可行性分析

| 维度 | 结论 | 说明 |
|---|---|---|
| 技术可行性 | ✅ 可行 | BM25（Neo4j 全文索引）、向量（已有）、图（已有）、RRF（纯 JS） |
| 数据条件 | ✅ 满足 | 275 味药材数据量小，三路检索性能无忧 |
| 中文分词 | ⚠️ 需验证 | cjk 分析器（bigram）对中文够用；不足则用 jieba 预处理 |
| **AuraDB Free 限制** | ⚠️ 关键风险 | 全文索引 + cjk 分析器在 Free 版的支持度需实测 |
| 向量依赖 | ⚠️ 可选 | 无 DASHSCOPE key 时降级为 BM25+图两路，不影响核心 |

### 关键风险与应对

1. **cjk 分析器兼容性**：先在本机/临时实例验证 `CREATE FULLTEXT INDEX ... cjk` 是否在 AuraDB Free 可用；不可用则退化为 `standard` 分析器 + jieba 预分词（空格分隔后建索引）。
2. **全文索引维护**：药材增删改后需保持索引同步（Neo4j 全文索引自动更新，无需手动）。
3. **图检索排名分**：当前图检索无 score，需按匹配字段优先级补一个简单分（如上表）。
4. **延迟**：三路并行 + RRF 是纯内存计算，额外延迟可忽略（毫秒级）。

> 「检索模块采用 **BM25 全文检索 + 向量语义检索 + 知识图谱检索** 三路并行，通过 **RRF（倒数排名融合）** 统一重排——相比单一检索，兼顾了字面精确、语义泛化与关系推理三个维度，显著提升中医药问答的命中率与召回率。」
